# Stellar Secretary v0.1.114

Fix iPhone pairing and reconnection when a reachable TCP port cannot complete secure communication with the Mac.

- Select a LAN, nearby Wi-Fi or Bluetooth carrier only after receiving an HTTPS response with the expected pinned Mac certificate. A TCP-only connection or a failed TLS upstream can no longer win the carrier race and prevent another working carrier from connecting.
- Check direct endpoints independently and retry them while wireless discovery continues, including when the Mac becomes available during an ongoing connection attempt.
- Discard a failed URLSession before reconnecting, while retaining the existing short foreground-resume reuse of working sessions.
- Add regression coverage for TCP readiness without TLS, wrong-certificate rejection and secure carrier selection before device approval.

The pairing fix is in the iPhone companion source and its updated development installation. Desktop installers include the matching shared native transport sources; updating only the desktop does not update an already installed iPhone app. The companion remains a development installation for iOS 17 or later, without App Store or TestFlight distribution.

Validation: 14 native tests against an isolated real TLS gateway, including certificate pinning and authenticated connection reuse; the complete iPhone simulator pairing, desktop approval, capture, search, foreground resume and offline-queue recovery flow; signed iPhone development build. The updated development build was installed on the existing iPhone for user trial. Desktop publication additionally requires full Python/JavaScript regression checks, three-platform builds and a signed, notarized Mac package.

中文：修复手机能连上 TCP 端口，却无法完成加密通信时配对超时的问题。局域网、邻近 Wi-Fi 和蓝牙通道现在通过 Mac 证书校验并收到 HTTPS 响应后才会被选中，失败通道不会抢占其他可用通道；发现期间持续重试直连地址，连接失败后清理失效会话。修复主要位于 iPhone 配套 App，必须使用更新后的手机开发版，单独更新电脑不会更新手机 App。已通过原生 TLS 与完整模拟器流程验证，并将开发版覆盖安装到现有 iPhone 供试用。
