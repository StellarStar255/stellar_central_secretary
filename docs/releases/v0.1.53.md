# Stellar Secretary v0.1.53

Add Gemini CLI and configurable model proxy connections.

- Select **Gemini · Gemini CLI** for summaries, full-document summaries, questions and explicitly attached images. Reuses the installed CLI authentication. Install the current Gemini CLI and run `gemini` once to sign in. The adapter was verified with CLI 0.66.0.
- Model connections now offer **Automatic**, **Direct**, and **Custom HTTP proxy**. The selected route applies to Claude, Codex, Gemini, custom model APIs and connection tests. Use your proxy app's HTTP / Mixed port, for example `http://127.0.0.1:7897`. SOCKS URLs and credentials in proxy URLs are not supported.
- Custom proxy failures report an error without falling back to a direct connection. Local model APIs bypass the external proxy. Browser capture and system proxy settings keep their existing behavior.
- Test the selected model using unsaved settings without sending archived material or changing the saved configuration. Connection tests have a bounded model deadline and no longer use the ordinary 12-second local-request timeout.
- Gemini calls disable model tools, hooks, extensions, MCP and global context. Literal `@file` references in archived text cannot expand local files; only explicitly attached images are loaded.
- **Open in default app** is now the first file action in item details.

Validation: 171 Python tests on macOS (169 passed, 2 conditional skips); JavaScript UI regression checks; real Chrome settings save/reload and Chinese/English interface checks. A real Gemini CLI and the isolated API worker were tested against synthetic local services and an HTTP CONNECT proxy with TLS verification enabled. No real Gemini cloud account was used in these tests.

Installers: Windows x64 setup EXE, Apple Silicon macOS DMG (Developer ID signed and notarized), and Linux x64 Debian / portable packages. Data remains outside the application installation directory and is preserved during upgrades.

Known Linux issue: an installed application has been reported not to open on Ubuntu 22.04. Investigation follows this release. Existing Linux package checks validate installation and headless server/API startup; they do not establish that launching from a graphical desktop works in the reported environment.
